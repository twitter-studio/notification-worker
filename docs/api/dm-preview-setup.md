# DM通知の本文表示を設定するAPI

接続APIのcapability `dm_preview_setup: true` があるWorkerで利用する。各APIはPOST、JSON、`Authorization: Bearer <接続済み端末の管理キー>` を要求する。応答は常に `Cache-Control: no-store`。運営APIへ送らない。

| パス                            | 本文                                                                                                                                              | 成功応答                                                                                                                   |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `/v1/pairing/dm-preview/start`  | `route_id`（UUID）、`request_id`（UUID）、`app_state`（22〜128文字のBase64URL乱数）。接続のログインで続けるときは `use_connect_login`（`true`）も | 201 `{"url":"https://<このWorker>/dm-preview?state=<不透明な値>"}`。`use_connect_login` のときは 201 `{"authorized":true}` |
| `/v1/pairing/dm-preview/finish` | 上記3項目と `key`（端末内で生成した32バイト一時鍵のBase64）                                                                                       | 200 `application/octet-stream` の暗号文（12バイトnonce + AES-GCM暗号文 + 16バイトtag）                                     |
| `/v1/pairing/dm-preview/cancel` | 最初の3項目                                                                                                                                       | 204                                                                                                                        |

JSON本文は1KiB以下。PINや復元した秘密鍵は送らない。`request_id` と `app_state` は最初から最後まで同じ値を使う。Workerから受け取ったURLは、元のWorkerと同じHTTPS originで、`/dm-preview` のURLか確認してから開く。

アプリはASWebAuthenticationSessionでURLを開く。Workerは確認ページを出さずにTwitterの許可の画面へ送り (2026-11-12)、PKCE・ブラウザCookieを検証し、Twitterから戻った認可コードを短期間だけ保管する。戻り先は `tweetbot-worker://dm-preview?state=<app_state>`。失敗時は `error=denied` も付く。確認ページや戻り先で、認証前の入口の上限 (`CONNECT_LIMITER`) に当たったときは `error=rate_limited` を付けて戻す (Xで断られた戻り先は `error=denied`)。アプリは待つように伝える。上限の中では書き込まないので、要求は10分で切れるか、同じルートの次の `/start` で置き換わる。どの要求か分からないときや、ログインを始めたブラウザでないときは、待つように書いた文のページ (429) を出す (#84)。戻り先のスキーム・host・state・引数の重複を照合してから `/finish` を呼ぶ。カスタムURLに一時鍵や暗号文は載せない。

## 接続のログインで続けて設定する (2026-11-12)

capability `dm_preview_login: true` があるWorkerでは、初めて接続するときのXのログインを、そのまま本文の設定に使える。利用者がXに2回ログインしなくて済むようにするため（ADR-0009の2026-11-12の変更）。

1. アプリは、接続の `/connect` に `dm_preview=1` を付ける。DMを選んだ接続でだけ受け、DMがなければ `error=invalid_request` で戻す。
2. Workerは、接続を終えてコードを出した後、そのログインの読み取りトークンを、接続した管理キー・本人・出したコードに結び付けて20秒だけ持つ。Durable Objectのメモリだけに置き、ストレージには書かない。期限の切れたものは、alarmでも消す。DMを選んだ接続のscopeは、本文の設定のscope（`tweet.read`、`users.read`、`dm.read`）を含む。含まなければ持たない。
3. アプリは接続の後、`/start` に `"use_connect_login": true` を付ける。同じ管理キーと本人の許可があり、ルートがそのログインで出したコードでつないだものなら、許可をこの要求に移して `201 {"authorized":true}` を返す。`/connect` の管理キーのハッシュは外から指定できるので、同じ管理キーで前からルートを持つ人が、本人のログインの許可を横から使えないようにする。ブラウザは開かず、そのまま `/finish` を呼ぶ。本人は接続のときに確かめてあるので、`/finish` はトークンの交換と本人の読み直しをしない。
4. 許可がない（期限切れ、Durable Objectの入れ替わり、使った後、ルートがそのログインのコードでつないだものでない）ときは410を返す。ルートを持たない管理キーは、ルートの照合で先に404になる。許可を使う `/start` は、成功しても410でも開始間隔（30秒）を使わない。アプリがすぐ、ブラウザでのログイン（`use_connect_login` なし）に戻れるようにするため。許可を使う回もXのログインが要り、IPごとの上限（`CONNECT_LIMITER`）にも掛かる。`/cancel` は、移した許可も捨てる。移した後に `/finish` の前に期限が切れたら、`/finish` は410を返し、アプリはブラウザでのログインに戻る。

後から設定し直すときは、今までどおりブラウザでログインする。

## 期限と制限

設定要求は10分で失効し、認可コードを受け取った後は20秒以内に `/finish` を呼ぶ。要求は使い切り。途中で接続解除された場合も無効。端末ごとの開始間隔は30秒以上（接続のログインの許可を使う `/start` を除く）、認証前の入口は既存の `CONNECT_LIMITER` でも制限する。

エラー: 400/422（不正な要求）、401（管理キーの形が不正）、403（読み取り認可・本人確認に失敗）、404（未対応/接続なし）、409（同アカウントの処理中）、410（期限切れ/取消/再利用）、413（サイズ超過）、429（上限）、503（上流の失敗）。アプリは機密情報を表示せず、再設定やWorker更新を案内する。

取得するのは本人のPIN復旧設定、署名公開鍵、最近20件の1対1の会話の暗号化された鍵変更。トークンや取得結果を永続保存しない（接続のログインのトークンは、メモリに20秒だけ持つ）。トークン交換後の本人照合を済ませてから読み取る。暗号文はTweetbotの既存 `twitter-studio/x-chat-setup/v1` の追加認証データ（本人、配送先UUID、要求UUID）に結び付く。

端末がPINで秘密鍵を復旧して公開鍵と照合した後、対象ルートのプレビュー鍵だけを設定する。通知種類と購読は変更せず、DM通知の購読はWorker接続時にDMを選択して用意する。グループ会話、新しい会話と鍵変更の自動追従は今回の対象外。新しい会話には再設定が必要。

[Xの会話一覧](https://docs.x.com/x-api/chat/get-chat-conversations)、[公開鍵](https://docs.x.com/x-api/chat/get-user-public-keys)、[会話イベント](https://docs.x.com/x-api/chat/get-chat-conversation-events)、[設計ADR-0009](https://github.com/twitter-studio/notification-docs/blob/main/docs/adr/0009-dm-preview-api-setup.md)。

会話一覧は空ページを含め最大5ページまで送り、外部要求は本人照合を含め50回以内に制限する。取得できた最近の会話を最大20件準備する。設定APIからXの購読を作成・削除しないため、途中の失敗やPIN入力のキャンセルで新しい購読は残らない。

会話の相手は、会話一覧の `participant_ids`（本人を含むかを問わない）か、会話IDの `<ユーザーID>-<ユーザーID>` から決める。会話IDが本人を含まない、グループ（`g` で始まる、または `type` が `direct` でない）、両者が食い違う、項目があるのに読めない、会話IDが文書の認める形（数字、`A-B`、`g` で始まる）のどれでもないといった会話は飛ばす。1ページは先頭の20行だけを使う。

本人の鍵は、署名に使う4項目で1件ずつ確かめ、形の合わない記録は捨てる。復旧に使う鍵は `juicebox_config` を持つ最新の版を選ぶ。選んだ版より新しい記録を読めなければ、古い鍵で準備せず503を返す。読める新しい版に `juicebox_config` がないときは、止めずに数える（どの版にも付くかをXの文書は書いておらず、実際のアカウントで確かめた #413 のCLIも同じ選び方だったため）。相手の鍵は署名に使う4項目だけで確かめる。`errors` の付いた応答は、会話一覧と相手の公開鍵では `data` が空でないとき、会話イベントでは `data` か `meta.conversation_key_events` が空でないときだけ部分的な失敗として通し、段階とproblemの種類ごとに数える。本人の公開鍵では、引けなかった記録が新しい版かもしれないので止める。`errors` が配列でない応答は、形の失敗として止める。

次の場合は、その会話を飛ばして読めた分で準備する。2ページ目以降の会話一覧を読めないとき、1つの会話でイベントや相手の公開鍵を読めないとき（200以外、本文の途中の切断や時間切れを含む）、40秒の締め切りや外部要求の上限に達したとき、署名鍵の合計がアプリの上限（100件）を超えるとき、材料がアプリの上限（131044バイト）を超えるとき。鍵変更のイベントは、アプリが受ける1件16384バイトまでのBase64だけを使う。鍵変更を1件も取れなければ503を返す（#71）。

`/finish` の結果は、本人照合の後、応答が決まってから `{"event":"dm_preview_setup"}` のログに1行残す。材料を集める処理の外（Durable Objectの呼び出しや暗号化）の失敗は `unexpected` として残す。`outcome` は `prepared`（200）、`failed`（503）、`route_gone`（410）、`too_large`（413）。失敗は段階（`own_keys`、`no_recovery_key`、`conversations`、`conversation_events`、`peer_keys`、`no_key_changes`、`deadline`、`budget`、`unexpected`）と、締め切りや上限に達した段階（`during`）を出す。あわせて、HTTPの状態、Xのproblemの種類、例外の名前、形のずれた項目の名前と種類、飛ばした会話や記録の理由ごとの数（`skipped`）、部分的な失敗の数（`partial`）を出す。値、ユーザーID、会話ID、トークン、本文は出さない。
