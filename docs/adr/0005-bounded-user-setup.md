# ADR-0005: 初回接続を期限付き購読と回復用台帳で行う

Status: Accepted / 2026-11-05。対象: [USER-002 #13](https://github.com/twitter-studio/notification-worker/issues/13)。設計書の本人認可とBYO構成を具体化する。通知のAPI契約・イベント正規化は変更しない。

## 背景

初回接続には利用者のX・Cloudflare・中継資格情報が関わる。OAuthだけでは本人一致・CRC・購読解除を確認できない。購読作成の応答喪失やプロセス停止でも、新規作成を繰り返して無期限の購読を残さない手段が必要。

## 判断

ローカルのNode CLIをplan/run/recoverに分ける。Cloudflareの作成・配置・秘密保存は扱わない。保護したGitHub Environmentによる配置とその権限管理はOPS-003へ分離する。既存Webhookの照合とCRC再検証だけを行い、アプリ・Webhookの発行、課金設定、規約同意は自動化しない。

runは専用アプリ、最小scope、同じClient IDで得たtoken、本人一致、残高、期限付きの所有者承認を確認する。購読は本人宛てmention/reply各1つ、明示期限30分。各通常要求で承認・token期限を再確認し、購読期限もその範囲内に収める。対象本人に既存購読がある場合は拒否する。他の管理操作を並行させない。App-only BearerのClient IDをAPIで直接証明するものではないため、同一専用アプリの資格情報を所有者が用意し、Webhook登録の照合で取り違えを検出する。

要求前に累積数を0600の台帳へ原子的に保存し、通常12回・解除を含め20回を超えない。単一ディレクトリの排他lockを使う。作成前に予定とtagを保存し、応答不明でもtag・本人・Webhook・種類の一致から今回の購読を発見する。recoverは新規作成や期限延長をせず、同じ台帳の残りの上限内で解除と不在確認だけを続ける。保存失敗時に台帳を更新せず追加通信する経路は作らない。

期限、Ctrl-C、通常の失敗で解除する。強制終了や障害では解除を保証できず、期限と手動回復が必要。一覧に続きがある場合は全件確認済みとしない。CLIの成功とは今回の購読不在を確認したことだけで、Worker停止・APNs到達・支出上限の保証ではない。終了後の入口無効化とQueue空の確認は運用手順に含める。

## 制約と検証

本人tokenにoffline.accessを追加せず、無期限運用や自動更新を実装しない。期限切れが購読解除を意味するとは仮定しない。クレジット残高を取得してもConsoleの支出上限と自動チャージ設定は確認できない。承認ファイルは本人の確認記録であり、独立したアクセス制御ではない。第三者の配信イベント数をAPI要求数の上限で制限できない。

HTTPの送信先・サイズ・timeout・リダイレクトを制限し、公開出力には固定状態と件数・期限だけを残す。本人ID・Webhook ID・秘密・応答本文はログへ出さない。台帳の手動削除による上限リセットは認めない。手順・一次資料・回復条件は [セットアップ手順](../../ops/setup.md) に置く。実X接続は別の範囲承認後のゲートとする。

## 継続利用の購読管理

30分の初回検証とは別に、本人が `x-activity-subscriptions.mjs` を使って作成・延長・解除を明示的に実行できる。期限は操作ごとに指定し、無期限の作成は明示指定とする。既存購読の延長には同じ本人、Webhook、種類、tag、購読IDを照合し、Xの作成APIに新しい期限を渡す。応答喪失時の再実行では、保存した操作と一覧の全ページから、完了した分と残りを判断する。強制終了時の扱い、認可の更新、解除後のWorker停止は[運用手順](../../ops/setup.md#継続する購読の作成延長解除)を参照。実接続試験の範囲は別に記録する。
