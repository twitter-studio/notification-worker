# 自分の Worker をアプリから設定する

初回設定、通知の種類、複数端末の追加、接続解除は [アプリからの接続手順](production-setup.md) を使います。配置は [Deploy to Cloudflare](../README.md#deploy-to-cloudflare-のボタンで配置する)、監視は [運用手順](README.md) を参照します。開発用アプリでも、`RELAY_URL` をそのアプリが登録した中継へ合わせて同じ接続手順を使います。

ローカルで本人 OAuth トークンを保存する CLI、期限付き・継続購読の CLI、接続コードの発行は廃止しました。過去の試験結果は [初回接続 CLI の検証記録](../docs/verification/2026-11-05-user-setup-cli.md) に残しています。現在の利用者へそのコマンドを案内しません。

## 鍵の更新と完全な削除

- 中継の資格情報はアプリから入れ替えます。古い値は直ちに無効になるため、接続済み Worker への更新結果と各端末の通知を確認します。
- App-only Bearer を変える場合は、同じ X アプリを使うほかの Worker も確認します。値をチャット・ログ・リポジトリへ残しません。本人トークンは接続の都度取得し、ローカルへ保存しません。
- 完全にやめる場合は、各アカウントの全接続を解除し、Worker が作った購読がなくなったことを確認します。手動購読は所有者が別途確認します。その後、専用かつ不要な Webhook・Worker・Queue・ローカルの秘密を、承認した範囲だけ削除します。

## X の Client Secret を更新する

1. 同じ X アプリを使う Worker・Webhook・アカウントを列挙し、停止範囲と再開条件について所有者の承認を得ます。
2. 計画的な更新では各端末の接続を解除し、Worker 所有の購読の片付けを待ちます。手動購読は[停止・回復手順](manual-subscription-cleanup.md)で停止し、対象購読の不在を確認します。
3. 利用者 Worker の Queue が空になったことを確認し、承認した配置で X/mock の入口を無効にします。`/health` は200、両 Webhook 入口は404、Queue の件数・bytes は0であることを確認します。
4. 所有者が X の Client Secret を再発行し、対象の全 Worker の `X_OAUTH2_CLIENT_SECRET` を承認した経路で更新します。値を表示せず、`X_EVENT_ID_SECRET` は変えません。古い Secret のまま受信を再開しません。
5. X の入口を有効にして `/setup` から Webhook の CRC を再確認します。有効と確認できなければ接続を再開せず、停止構成を維持して新しい Secret と対象アプリを照合します。
6. 各アカウント・端末を再接続し、Worker 経由テスト通知と実イベントの到達を確認します。以前の手動購読のうち必要な種類はアプリで選びます。他用途の購読はその所有者の手順で復旧します。

漏えい時は Queue が空になるのを待たず先に失効・入口停止し、通知欠落を許容して止めます。再開は所有者が承認し、保存してある古い Secret や旧ジョブを無条件に戻しません。

## 通知プレビュー

1. プレビューに対応した運営 API が稼働していることを確認する。利用者 Worker を対応版へ更新し、自分の Wrangler 設定の `vars` に `ENABLE_X_NOTIFICATION_PREVIEW="true"` を追加する。共有の sandbox Workflow では未設定のままなので、プレビューは有効にならない。
2. イベントに公開投稿者の情報がない場合も表示するには、同じ X アプリの App-only Bearer Token を利用者 Worker の `X_PREVIEW_BEARER_TOKEN` secret に置く。X の利用料を確認してから設定する。Worker は情報が欠けているイベントでだけユーザー照会を1回試す。運営や GitHub にトークンを渡さない。いいね・リツイートで元のツイートがイベントにない場合、`ENABLE_X_POST_PREVIEW_LOOKUP="true"` を追加すると公開ツイートを照会する。この設定を省略すると Post Lookup は行わない。DM の本文表示を設定した端末がある場合は、送った人を端末の鍵で暗号化した中身に入れる。通常の DM は Webhook の `users` を使い、X Chat と、`users` にない通常の DM だけを、送った人ごとに 1 回照会する (#73)。[X の User Lookup](https://docs.x.com/x-api/users/get-user-by-id)
3. メンションと直接返信を1件ずつ送り、各端末の通知に @ユーザー名と抜粋が出ること、タップで対象の投稿が開くことを確認する。投稿者を確認できない場合は定型文で届く。

プレビュー非対応の版に戻す場合は、まず対応版のまま `ENABLE_X_NOTIFICATION_PREVIEW="false"` を反映する。利用者 Worker と運営 API の両 Queue で待機中・遅延中のジョブがなくなったことを確認してから旧版へ戻す。旧版はプレビュー付きの要求や待機ジョブを受け付けない。

プレビューが定型文になる場合は、Worker ログの `x_preview_lookup` で照会結果と HTTP ステータスを確認する。照会に使ったユーザー ID、URL、本文、資格情報はログに記録しない。
照会ログがない場合は、プレビューの設定、照会用 secret、イベントに本文があるかを確認する。展開済みの投稿者情報だけでプレビューを作れた場合も、照会ログは出ない。

X の Webhook が 422 を返した場合は、Worker ログの `x_webhook_validation_rejected` で検証段階と項目を確認する。項目名は固定リストに限り、配列の添字は `*` で表す。入力値や生の検証エラーは記録しない。

最上位の形式で失敗した場合は `shape` も確認する。最上位と `data` の種類、および固定リストにある目印の有無だけを記録する。目印の値とリストにないキーは記録しない。
